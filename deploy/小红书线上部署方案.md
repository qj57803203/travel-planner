# 小红书线上部署方案

> 主方案：MCP 容器（xiaohongshu-mcp），通过 MCP 协议调用搜索/详情/登录等工具。
> 登录方式：后端调 MCP 的 get_login_qrcode 获取二维码，开发者扫码即可。
> CDP 直连方案已注释保留，可作为降级参考。

## 方案说明

### 主方案：MCP 容器（当前使用）

| 维度 | 说明 |
|---|---|
| **镜像** | xpzouying/xiaohongshu-mcp（独立容器） |
| **原理** | MCP 服务内置无头浏览器，后端通过 MCP Streamable HTTP 协议调用搜索/详情接口 |
| **内存** | ~361 MiB |
| **登录方式** | MCP 的 get_login_qrcode 返回二维码 base64，开发者手机扫码 |
| **Cookie 存储** | `/app/data/cookies.json`（容器内），通过 volume 挂载到宿主机 `./xhs/data/` |
| **优势** | 部署简单、登录流程自动化、自带 Cookie 持久化、资源隔离 |
| **劣势** | 内存占用比 CDP 方案高 |

### 备用方案：CDP 直连 Chrome（已注释保留）

| 维度 | 说明 |
|---|---|
| **镜像** | chromedp/headless-shell（共用） |
| **原理** | 后端通过 WebSocket 直连 Chrome，用 CDP 协议控制浏览器访问网页、提取 DOM |
| **内存** | ~222 MiB（共用 Chrome） |
| **登录方式** | 网页截图扫码 / 浏览器导出 Cookie |
| **优势** | 资源占用低、与携程共用 Chrome |
| **劣势** | 登录流程复杂、DOM 解析不稳定 |

**结论**：使用 MCP 方案作为唯一小红书数据源，CDP 方案代码保留但不启用。

## 部署步骤

### 1. 配置环境变量

在 `deploy/backend.env` 中确保配置了 MCP 地址：

```env
# 小红书 MCP（主力方案）
XHS_MCP_URL=http://xiaohongshu-mcp:18060/mcp
```

### 2. 启动服务

```bash
cd ~/travel-planner/deploy

# 首次启动（会自动拉取 MCP 镜像）
sudo docker compose up -d

# 检查状态
sudo docker ps
```

### 3. 首次登录

1. 访问 `http://服务器IP/xhs-login.html`
2. 点击「获取登录二维码」按钮
3. 等待 10-20 秒（MCP 服务启动浏览器）
4. 用手机小红书 App 扫描二维码
5. 登录成功后 Cookie 自动保存

### 4. 验证

```bash
# 检查 MCP 容器状态
sudo docker ps | grep xiaohongshu-mcp

# 查看后端日志（应显示 "小红书：使用 MCP 方案采集笔记"）
sudo docker logs travel-backend --tail 50

# 检查 Cookie 文件
ls -la ~/travel-planner/deploy/xhs/data/cookies.json
```

## 登录流程详解

### MCP 二维码登录（当前方案）

```text
1. 前端调 GET /api/xhs-qrcode
2. 后端通过 MCP 调 get_login_qrcode 工具
3. MCP 服务启动浏览器 → 打开小红书首页 → 提取二维码图片（base64）
4. MCP 在后台 goroutine 等待扫码（最多 4 分钟）
5. 后端返回 {qrcode, timeout, already_logged_in} 给前端
6. 前端展示二维码 + 倒计时
7. 开发者用手机小红书 App 扫码
8. MCP 每 500ms 检测登录状态 → 登录成功 → 保存 cookies.json
9. 前端轮询 /api/xhs-login-status → 检测到已登录 → 显示成功
```

### Cookie 生命周期

- MCP 服务启动时自动从 `cookies.json` 加载
- 登录成功后自动保存到 `cookies.json`（v2 格式，含 seed + 时间戳）
- Cookie 过期后（7-30 天），重复上述扫码流程
- `cookies.json` 通过 volume 挂载到宿主机 `./xhs/data/`，容器重建不丢失

## 常见问题

### Cookie 过期了怎么办？

访问 `http://服务器IP/xhs-login.html`，重新扫码登录即可。Cookie 自动保存，无需手动操作。

### 获取二维码超时怎么办？

MCP 服务首次启动浏览器可能需要 10-20 秒。如果超时：
1. 检查 MCP 容器状态：`sudo docker ps | grep xiaohongshu-mcp`
2. 查看 MCP 日志：`sudo docker logs xiaohongshu-mcp --tail 50`
3. 重启 MCP 容器：`sudo docker compose restart xiaohongshu-mcp`

### MCP 容器启动失败怎么办？

1. 检查端口占用：`netstat -tlnp | grep 18060`
2. 检查 Cookie 文件权限：`ls -la deploy/xhs/data/`
3. 查看日志：`sudo docker logs xiaohongshu-mcp`

### 如何切换回 CDP 方案？

1. 在 `backend/app/agent/nodes.py` 中取消 CDP 代码的注释
2. 在 `backend/app/routers/trips.py` 中恢复旧的截图登录接口
3. 在 `deploy/docker-compose.yml` 中注释掉 MCP 容器
4. 重新构建部署

## 演化历程

xiaohongshu-mcp占用内存大，所以先考虑的用go爬虫常用的轻量浏览器库chromedp，验证无头能不能进xhs页面（截图传回本地看），但用这个库浏览器总是卡死或超时，可能是Python中用法太少或是什么。并且及时可行，解析xhs的dom结构提取信息也麻烦，就放弃此方案了。

xiaohongshu-mcp：研究了这个库，小红书网页端用的是 React + Redux，页面加载后会把服务端渲染的数据注入到 window.__INITIAL_STATE__ 这个全局变量，所以这个库就直接解析这个变量就行，不需要解析dom和分析接口，所以没什么风险。
