# 交通规划逻辑

## 整体流程

```
┌─────────────────────────────────────────────────────────────────────┐
│                         行程生成流程                                  │
└─────────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────────┐
│  extract（LLM）  │ 从自然语言抽取偏好（含 departure, destination）    │
└─────────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────────┐
│  research        │ 搜集信息素材（预置数据 + 小红书攻略）              │
└─────────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────────┐
│  plan（LLM）     │ 生成每日行程 + 建议城际交通方式                    │
│                  │ 输出：markdown, days, transport_mode, transport_reason │
│                  │ 关键：days 的 spots 顺序必须是最优动线，不绕路不回头 │
└─────────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────────┐
│  transport       │ 查高德 API，生成真实交通，注入行程                  │
└─────────────────────────────────────────────────────────────────────┘
```

## transport 节点详解

transport 节点负责两件事：
1. **城际交通**：出发地 → 目的地（仅用于行程文字展示，不在地图上画线）
2. **市内交通**：每天景点之间的交通（地图上按天分色画线）

### 数据流

```
输入：
  preferences: {departure, destination}
  plan_days: [{day: 1, spots: ["景点A", "景点B"]}, ...]
  transport_mode: "train" | "flight" | "driving"
  transport_reason: "理由"
  itinerary: "行程 markdown"

输出：
  transit: {
    source: "amap" | "none",
    transport_mode: str,
    transport_reason: str,
    inter_city: {...} | null,    // 城际交通
    days: [{day, legs[...]}],    // 市内交通
  }
  itinerary: "注入交通后的完整行程"
```

## 城际交通

### 决策逻辑

```
                    ┌─────────────────┐
                    │ transport_mode  │
                    └────────┬────────┘
                             │
           ┌─────────────────┼─────────────────┐
           │                 │                 │
           ▼                 ▼                 ▼
    ┌──────────┐      ┌──────────┐      ┌──────────┐
    │  train   │      │  flight  │      │ driving  │
    └────┬─────┘      └────┬─────┘      └────┬─────┘
         │                 │                 │
         ▼                 ▼                 ▼
  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐
  │ railway_route│  │ 文字提示     │  │ driving_route│
  │ （查铁路）   │  │ （高德不支持）│  │ （查驾车）   │
  └──────┬───────┘  └──────────────┘  └──────────────┘
         │
         │ 失败
         ▼
  ┌──────────────┐
  │ driving_route│
  │ （降级驾车） │
  └──────────────┘
```

### 调用高德 API

| 交通方式 | 调用函数 | 高德 API | 备注 |
|---------|---------|---------|------|
| train | `railway_route()` | `/v3/direction/transit/integrated` | 只提取 railway 段 |
| flight | - | - | 高德不支持航班，返回文字提示 |
| driving | `driving_route()` | `/v3/direction/driving` | 直接查驾车路线 |

### railway_route 函数

```
输入：origin（起点经纬度）, dest（终点经纬度）, city（起点城市）, cityd（终点城市）
输出：{mode, summary, duration_min, distance_m, polyline} | None

逻辑：
1. 调用高德公交 API（/v3/direction/transit/integrated）
2. 遍历 segments，只提取 railway 段（忽略 walking/bus）
3. 拼接 summary："车次名 出发站→到达站"
4. 无铁路段时返回 None（调用方降级为驾车）
```

## 市内交通

### 决策逻辑

```
                    ┌─────────────────┐
                    │ 计算两点距离    │
                    │ （先查驾车）    │
                    └────────┬────────┘
                             │
                ┌────────────┴────────────┐
                │                         │
                ▼                         ▼
         ┌───────────┐             ┌───────────┐
         │ distance  │             │ distance  │
         │  < 2km    │             │  >= 2km   │
         └─────┬─────┘             └─────┬─────┘
               │                         │
               ▼                         ▼
        ┌──────────────┐         ┌──────────────┐
        │ walking_route│         │ 对比耗时     │
        │ （步行）     │         │ 驾车 vs 地铁 │
        └──────────────┘         └──────┬───────┘
                                        │
                          ┌─────────────┴─────────────┐
                          │                           │
                          ▼                           ▼
                   ┌──────────────┐           ┌──────────────┐
                   │ 地铁更快     │           │ 驾车更快     │
                   │ metro_route  │           │ driving_route│
                   └──────────────┘           └──────────────┘
```

### 调用高德 API

| 场景 | 调用函数 | 高德 API | 备注 |
|-----|---------|---------|------|
| 步行 | `walking_route()` | `/v3/direction/walking` | 距离 < 2km |
| 地铁 | `metro_route()` | `/v3/direction/transit/integrated` | 只提取地铁线路 |
| 驾车 | `driving_route()` | `/v3/direction/driving` | 默认方式 |

### walking_route 函数

```
输入：origin（起点经纬度 "lng,lat"）, dest（终点经纬度 "lng,lat"）
输出：{mode, summary, duration_min, distance_m, polyline} | None

逻辑：
1. 调用高德步行 API（/v3/direction/walking）
2. 取 paths[0]，提取 duration、distance
3. 遍历 steps[] 拼接 polyline（高德步行 API 的 polyline 在 steps 里，不在 path 层）
4. 返回精简结果
```

### driving_route 函数

```
输入：origin（起点经纬度 "lng,lat"）, dest（终点经纬度 "lng,lat"）
输出：{mode, summary, duration_min, distance_m, polyline} | None

逻辑：
1. 调用高德驾车 API（/v3/direction/driving）
2. 取 paths[0]，提取 duration、distance
3. 遍历 steps[] 拼接 polyline（高德驾车 API 的 polyline 在 steps 里，不在 path 层）
4. 返回精简结果
```

### metro_route 函数

```
输入：origin（起点经纬度）, dest（终点经纬度）, city（城市）
输出：{mode, summary, duration_min, distance_m, polyline} | None

逻辑：
1. 调用高德公交 API（/v3/direction/transit/integrated）
2. 遍历 segments 中的 bus 段
3. 只保留名称含"地铁"或"轨道交通"的线路（忽略普通公交）
4. 拼接 summary："地铁X号线 出发站→到达站"
5. 无地铁线路时返回 None
```

### _build_legs 函数

```
输入：spots（景点名列表）, city（城市）
输出：legs（交通段列表）

逻辑：
1. 批量地理编码：景点名 → 经纬度（失败的景点打 warning 日志）
2. 逐段查交通：
   ├── 查 driving_route 获取距离
   ├── 距离 < 2km → walking_route
   └── 距离 >= 2km → 对比 driving_route 和 metro_route 耗时
       ├── 地铁更快 → metro_route
       └── 驾车更快 → driving_route
3. 每段校验 polyline 是否有效，空则打 error 日志
4. 返回 legs 列表 + 汇总日志
```

## 注入行程

### _inject_transit 函数

```
输入：itinerary（行程 markdown）, transit（交通数据）
输出：注入交通后的完整行程

逻辑：
1. 城际交通 → 注入到行程开头
   格式：**🚄 城际交通（高铁/火车）**
        - 从 合肥 到 苏州：G7063 合肥南→苏州
        - 💡 理由

2. 市内交通 → 按 Day 分割行程，交通信息穿插在景点之间
   格式：
        - 🏛️ 苏州博物馆（2小时）
        - 🚶 步行 0.9km · 11分钟
        - 🏘️ 平江路历史街区（1.5小时）
        - 🚇 地铁 · 15分钟
        - 🌙 山塘街（晚餐+夜游）
```

## 地图展示（前端 MapRoute.vue）

### 渲染规则

- **只画景区间路线**，不画城际交通（出发地→目的地不显示在地图上）
- **按天分色**：每天路线用不同颜色（蓝→红→绿→橙→紫……最多 10 种循环）
- **Day 标签**：在每天路线的中间位置显示 "Day N" 彩色气泡
- **景点标记**：实心圆点（颜色跟随所属天的路线色）+ 名称文字（白底描边，无黑框）
- **城际路线**：已移除，不在地图上画线

### 数据诊断日志

前端 `render()` 函数内置完整诊断，打开浏览器 F12 控制台可看到：

- `transit` 完整数据（JSON）
- `hasData` 判断结果及原因
- 每天 legs 数量、polyline 点数、首尾坐标
- 坐标缺失、polyline 无效等异常
- 汇总：总 polyline 数，0 条时报警

### 高德 polyline 提取要点

高德不同 API 的 polyline 位置不同：

| API | polyline 位置 | 提取方式 |
|-----|-------------|---------|
| 步行 `/v3/direction/walking` | `path.steps[].polyline` | 遍历 steps 拼接 |
| 驾车 `/v3/direction/driving` | `path.steps[].polyline` | 遍历 steps 拼接 |
| 公交/铁路 `/v3/direction/transit/integrated` | `segment.bus.buslines[].polyline` 或 `segment.railway.lines[].polyline` | 遍历 lines 拼接 |

> ⚠️ 步行/驾车 API 的 polyline **不在 path 层**，必须从 `steps[]` 里取。之前曾因此导致所有路段 polyline 为空。

## plan 节点的路线优化提示词

`prompts.py` 中 `PLAN_PROMPT` 对 days 的 spots 顺序有明确要求：

> spots 顺序就是实际游览的先后顺序，必须是地理上的流畅动线（如：由远到近、顺时针环线、沿地铁线等），绝不绕路、不走回头路。

这确保 LLM 生成的景点序列是合理的地理动线，后续高德查询得到的交通路线也是流畅的。

## 完整调用链

```
plan_transport(state)
│
├── 1. 城际交通
│   │
│   ├── transport_mode == "train"
│   │   ├── railway_route() → 成功 → inter_city
│   │   └── railway_route() → 失败 → driving_route() → inter_city
│   │
│   ├── transport_mode == "flight"
│   │   └── 文字提示 → inter_city
│   │
│   └── transport_mode == "driving"
│       └── driving_route() → inter_city
│
├── 2. 市内交通
│   │
│   └── for each day in plan_days:
│       └── _build_legs(spots, city)
│           │
│           └── for each 两个相邻景点:
│               ├── driving_route() → 获取距离
│               ├── distance < 2km → walking_route()
│               └── distance >= 2km
│                   ├── metro_route()
│                   ├── driving_route()
│                   └── 选耗时短的
│
└── 3. 注入行程
    └── _inject_transit(itinerary, transit)
        ├── 城际交通 → 行程开头
        └── 市内交通 → 穿插在每天景点之间
```

## 文件清单

| 文件 | 函数 | 职责 |
|-----|------|------|
| `amap.py` | `geocode()` | 地名 → 经纬度 |

| `amap.py` | `metro_route()` | 市内地铁路线 |
