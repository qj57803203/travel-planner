# 生成行程改为「步骤进度」实时推送

## Context

当前「生成行程」是一次同步调用：前端 `POST /api/generate` → 后端 `agent_graph.invoke` 一次性跑完三步（extract → research → plan）→ 返回完整 `Trip`。期间前端只有一个「正在规划…」的 loading，用户看不到走到哪一步；而 `research` 阶段含小红书 MCP 调用，最长可耗时 75s+，体验上像「卡住了」。

目标：把三步流程的**步骤进度**实时推送到前端，让用户看到「抽取偏好 → 搜集信息 → 生成行程」三步依次推进。**行程文本仍一次性展示**（不做 token 级逐字流式，用户已确认此粒度）。

方案选型：**SSE（Server-Sent Events）**，单向服务端推流，最贴合「后端推进度」；不用 WebSocket（无双向交互需求）。

---

## 后端改动

### 1. `backend/app/routers/trips.py` — 新增流式端点

新增 `POST /api/generate/stream`，用 `StreamingResponse` + `media_type="text/event-stream"`。核心：用 LangGraph 的 **`astream(stream_mode="updates")`** 替代 `invoke` —— 每完成一个节点，`updates` 模式就 yield 一个 `{节点名: 增量dict}`，键即节点名，天然是进度来源，且**保留现有 `graph.py` 的三步 DAG 架构不变**。

```python
import json
from fastapi.responses import StreamingResponse

STAGE_MESSAGES = {
    "extract": "偏好已确认",
    "research": "素材已就绪",
    "plan": "行程已生成",
}

def _sse(payload: dict) -> str:
    return f"data: {json.dumps(payload, ensure_ascii=False)}\n\n"

@router.post("/generate/stream")
async def generate_trip_stream(req: GenerateRequest, db: Session = Depends(get_db)):
    if not req.user_input.strip():
        raise HTTPException(status_code=400, detail="输入不能为空")

    async def event_gen():
        state = {"user_input": req.user_input}
        try:
            async for chunk in agent_graph.astream(state, stream_mode="updates"):
                for node, update in chunk.items():
                    state.update(update)  # 手动累积，循环结束即完整 state
                    yield _sse({"type": "stage", "stage": node,
                                "status": "done", "message": STAGE_MESSAGES.get(node, "")})
        except Exception as e:
            yield _sse({"type": "error", "message": f"生成失败: {e}"})
            return

        trip = Trip(
            user_input=req.user_input,
            preferences=state.get("preferences", {}),
            research=state.get("research", {}),
            itinerary=state.get("itinerary", ""),
        )
        db.add(trip); db.commit(); db.refresh(trip)
        yield _sse({"type": "done", "trip": _to_response(trip).model_dump()})

    return StreamingResponse(event_gen(), media_type="text/event-stream")
```

要点：
- 复用现有 `_to_response()`、`Trip` 模型、`get_db` 依赖，不重复造轮子。
- `state.update(update)` 手动累积 `AgentState`，循环结束后 `state` 即含 `preferences`/`research`/`itinerary`，直接落库（与旧 `/generate` 的落库字段一致）。
- `astream` 的同步节点（`extract`/`research`/`plan` 都是 `def`）由 LangGraph 自动放到 executor 跑，`research` 里的同步 MCP 调用不会阻塞事件循环。
- 旧的 `POST /api/generate` **保留不动**，作为非流式兜底；历史查看用的 `GET` 接口不受影响。

- `graph.py` / `nodes.py` / `state.py` / `schemas.py`：**无需改动**。`agent_graph` 已导出，`astream` 直接可用。

## 前端改动

### 3. `frontend/src/types/index.ts` — 新增流式类型

```typescript
export type StageKey = 'extract' | 'research' | 'plan'
export type StageStatus = 'pending' | 'running' | 'done'

export interface StreamEvent {
  type: 'stage' | 'done' | 'error'
  stage?: StageKey
  message?: string
  trip?: Trip
}
```

### 4. `frontend/src/api/trips.ts` — 新增流式请求

用原生 `fetch` 读 SSE 流（axios 对流式支持不友好），逐段解析 `data:` 行。删除不再使用的旧 `generateTrip`（axios POST）。

```typescript
export async function generateTripStream(
  userInput: string,
  onEvent: (e: StreamEvent) => void,
): Promise<Trip> {
  const resp = await fetch('/api/generate/stream', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ user_input: userInput }),
  })
  if (!resp.ok || !resp.body) throw new Error('生成失败，请检查后端服务是否启动')
  const reader = resp.body.getReader()
  const decoder = new TextDecoder()
  let buf = ''
  let trip: Trip | null = null
  while (true) {
    const { done, value } = await reader.read()
    if (done) break
    buf += decoder.decode(value, { stream: true })
    const parts = buf.split('\n\n')
    buf = parts.pop() ?? ''
    for (const part of parts) {
      const line = part.trim()
      if (!line.startsWith('data:')) continue
      const e = JSON.parse(line.slice(5).trim()) as StreamEvent
      if (e.type === 'done') trip = e.trip ?? null
      else onEvent(e)
    }
  }
  if (!trip) throw new Error('生成失败，请检查后端服务是否启动')
  return trip
}
```

### 5. `frontend/src/store/trip.ts` — 状态 + 流式 action

新增 `stages` 状态（三步各 pending/running/done），`generate` 改走流式，回调里实时更新阶段：

```typescript
const STAGES: { key: StageKey; label: string }[] = [
  { key: 'extract', label: '抽取偏好' },
  { key: 'research', label: '搜集信息' },
  { key: 'plan', label: '生成行程' },
]
const stages = ref<Record<StageKey, StageStatus>>({ extract: 'pending', research: 'pending', plan: 'pending' })

function resetStages() { stages.value = { extract: 'pending', research: 'pending', plan: 'pending' } }

async function generate(input: string) {
  loading.value = true
  error.value = ''
  resetStages()
  stages.value.extract = 'running'          // 提交即进入第一步
  try {
    current.value = await api.generateTripStream(input, (e) => {
      if (e.type === 'stage' && e.stage) {
        stages.value[e.stage] = 'done'
        // 线性流程：标记下一步为 running
        const next = STAGES.findIndex(s => s.key === e.stage) + 1
        if (STAGES[next]) stages.value[STAGES[next].key] = 'running'
      } else if (e.type === 'error') {
        error.value = e.message || '生成失败'
      }
    })
    await loadHistory()
  } catch (e) { /* 沿用现有错误提取逻辑 */ }
  finally { loading.value = false }
}
```

返回里追加导出 `stages`、`STAGES`。

### 6. `frontend/src/components/GenerateProgress.vue` — 新建进度条组件

自绘三步进度条（对齐项目现有 CSS 变量与审美，不用 el-steps 避免样式定制）：
