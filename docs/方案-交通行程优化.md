# 交通行程优化方案

## Context

用户反馈三个问题：
1. 城际交通无脑用驾车路线，应该根据距离让 LLM 判断交通方式（驾车/高铁/飞机）
2. 需要用高德显示具体路线图
3. 前端地图只显示空白地图，路线不显示（高德 key 已配置）

## 实现方案

### 1. 在 plan 节点顺带判断交通方式

**文件**: `backend/app/agent/prompts.py` - `PLAN_PROMPT`

**改动点**:
- 在 PLAN_PROMPT 中增加 `transport_mode` 字段要求
- 让 LLM 在生成行程时，根据出发地和目的地距离，顺带输出建议的交通方式
- 交通方式选项：`driving`（驾车）、`train`（高铁/火车）、`flight`（飞机）

**输出格式扩展**:
```json
{
  "markdown": "...",
  "days": [...],
  "transport_mode": "train",
  "transport_reason": "距离约 800km，高铁最便捷"
}
```

### 2. 修改 plan_transport 节点逻辑

**文件**: `backend/app/agent/nodes.py` - `plan_transport` 函数

**改动点**:
- 从 state 中读取 LLM 建议的 `transport_mode`
- 根据 mode 调用不同 API：
  - `driving`：调用 `amap.driving_route`（已有）
  - `train`：调用 `amap.transit_route`（高德公交 API 包含铁路段）
  - `flight`：高德不支持航班查询，用 web 搜索获取参考信息（限制 token 消耗）

### 3. 增强 amap.py 支持更多交通方式

**文件**: `backend/app/tools/amap.py`

**改动点**:
- 确认 `transit_route` 返回的 railway 段 polyline 正确解析
- 可能需要新增 `train_route` 函数专门查铁路（或复用 transit_route）

### 4. 调试前端地图显示

**文件**: `frontend/src/components/MapRoute.vue`

**排查点**:
- 检查 `transit` prop 数据结构是否与后端一致
- 检查 `polyline` 数据格式（应为 `[[lng, lat], ...]`）
- 添加 console.log 调试数据流

### 5. 数据结构对齐

后端 `plan_transport` 返回的 transit 数据结构需与前端 `TransitInfo` 类型一致：
- `source`: 'amap' | 'none'
- `inter_city`: { from, to, mode, summary, duration_min, distance_m, polyline }
- `days`: [{ day, legs: [{ from, to, mode, summary, duration_min, distance_m, polyline }] }]

## 验证方式

1. 后端：调用 `/api/generate` 生成行程，检查返回的 `transit` 字段
2. 前端：切换到「地图路线」tab，检查是否显示 markers 和路线
3. 检查浏览器控制台是否有错误
