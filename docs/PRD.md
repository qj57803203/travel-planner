# PRD：个人旅行规划agent助手

## 1. 产品定位

面向个人自用的旅行规划工具。

用户输入一句旅行需求，系统自动搜集整理酒店、攻略、美食、交通等信息，并生成一份每日行程。用户不需要自己翻遍各种攻略。

---

## 2. 产品目标

让用户「输入需求 → 拿到一份可用的旅行计划」。

MVP 只验证一件事：**能自动把散落的信息汇总起来，并生成一份像样的行程。**

---

## 3. 用户使用流程

```text
1. 用户打开页面，输入旅行需求（如“9 月去东京玩 5 天，不想太累”）
2. 系统抽取目的地、天数、偏好
3. 系统自动搜集整理信息：酒店候选、攻略要点、美食、交通
4. 系统生成每日行程
5. 用户查看结果，保存或重新生成
```

## 5. 核心功能

### 5.1 需求输入与偏好抽取

用户输入自然语言需求。

示例：

```text
我 9 月去东京玩 5 天，喜欢美食和拍照，不想太累，酒店希望靠近地铁。
```

系统抽取为结构化偏好：

```json
{
  "destination": "东京",
  "days": 5,
  "pace": "轻松",
  "interests": ["美食", "拍照"],
  "hotel_preference": ["靠近地铁"]
}
```

### 5.2 信息汇总

系统自动搜集并整理四类信息，合并为一份旅行资料：

```text
酒店候选：名称、价格、评分、位置、优缺点
攻略要点：必去景点、推荐路线、避坑点
美食：推荐餐厅、热门美食
交通：市内交通方式、常用路线
```

### 5.3 行程生成

根据目的地、天数、偏好和信息汇总，生成每日行程。

生成原则：

```text
同一天安排相近区域，避免来回横跨
“轻松”模式下减少景点数量
热门景点安排在合适时间段
晚上优先安排商圈、美食、夜景
保留休息时间
```

输出示例：

```text
Day 1：抵达 + 新宿周边
上午：抵达东京，前往酒店寄存行李
下午：新宿御苑、新宿站周边
晚上：歌舞伎町、思出横丁晚餐

Day 2：涩谷 + 原宿
上午：涩谷 Sky、忠犬八公
下午：原宿竹下通
晚上：涩谷周边晚餐和购物
```

---

## 6. 页面设计

单页即可，三段式布局：

```text
左侧：旅行需求输入区
右侧：行程结果 + 搜集到的信息素材
底部：生成行程 / 重新生成 / 保存
```

---

## 7. 验收标准

```text
能根据一句需求抽取目的地、天数、偏好
能自动汇总酒店、攻略、美食、交通四类信息
能生成按天划分的每日行程
行程能体现用户偏好（如“轻松”则景点较少）
结果可保存
```

---

## 8. 后续规划

按优先级逐步加入：

```text
第一阶段（当前 MVP）：信息汇总 + 生成行程
第二阶段：酒店对比与推荐排序、预算估算
第三阶段：多轮修改（根据反馈重新规划）
第四阶段：Chrome DevTools MCP 控制真实浏览器，读取登录后内容
```
