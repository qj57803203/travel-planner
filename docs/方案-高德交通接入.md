# 接入高德真实交通（文本换乘 + 地图路线 + 出发地记忆）

## Context（为什么做）

当前行程只到「每天玩什么」，没有「怎么去」：既不知道从哪出发，也没有景点之间的实际交通。这次要：

1. **出发地**：生成后追问一次、记住（SQLite），下次自动补全；用户输入里主动提到「从 X 出发」则直接提取。
2. **真实交通**：接入高德地图，拿到景点间的实际换乘（地铁/公交/步行 + 时长），并在地图上画出路线。
3. **范围不设限**：市内景点间 + 城际（出发地→目的地）都接。

## 前置：高德开放平台申请（需你操作）

去 [lbs.amap.com](https://lbs.amap.com) 注册并完成**个人认证**，创建应用后加**两个平台类型**，各拿一套凭据：

| 平台类型 | 用途 | 凭据 | 填到哪 |
|---|---|---|---|
| Web 服务 | 后端 HTTP 查路径/地理编码 | `key` | `backend/.env` → `AMAP_WEB_KEY` |
| Web端(JS API) | 前端渲染地图 | `key` + `安全密钥 securityJsCode` | `frontend/.env` → `VITE_AMAP_JS_KEY` / `VITE_AMAP_SECURITY_CODE` |

**费用（个人够用，不用担心）**：个人认证开发者路径规划（驾车/公交/步行/骑行）**每日免费 5000 次**、地理编码免费；JS API 免费。超出后基础 LBS 服务约 30 元/万次。你这个个人工具远用不到付费档。JS API 2.0 从 2021 年起**强制要求 securityJsCode**，且 key 要绑定域名（开发期把 `localhost` 加进白名单）。

## 架构总览

```
extract → research → plan → transport → END
  (提取出发地)  (素材)   (生成行程   (查高德，
               +结构化景点序列)  注入交通+存路线)
```

关键点：景点序列是 `plan` 才生成的，所以交通节点必须放在 `plan` 之后。为此 **`plan` 改输出结构化 JSON**：`{markdown, days:[{day, spots:[...]}]}`，交通节点据此逐站查高德。

数据流：后端 Web 服务 API 查路径 → 返回结构化 `transit`（含每站经纬度 + 路线 polyline，均为 GCJ-02 坐标系，与 JS API 一致无需转换）→ 前端 JS API 只负责渲染 marker + polyline，**不重复规划**。

## 后端改动

### 1. `config.py`
加 `amap_web_key: str = ""`（空 = 不启用交通，静默降级走纯文本）。

### 2. `requirements.txt`
加 `httpx`（现有只有 fastapi/sqlalchemy/langchain，无 HTTP 客户端）。

### 3. `models.py`
- 新增 `UserProfile` 表（单行：`id`、`departure_city`、`updated_at`），存「记住的出发地」。
- `Trip` 表加 `transit` JSON 列（可空），存结构化交通结果。

### 4. `tools/amap.py`（新建）
封装高德 Web 服务 API（`httpx` 同步调用，超时 8s，失败返回 None 不抛）：
- `geocode(address, city) -> (lng, lat) | None` — `GET /v3/geocode/geo`
- `transit(origin_lnglat, dest_lnglat, city) -> dict | None` — `GET /v3/direction/transit/integrated`（市内换乘主接口）
- `driving(origin_lnglat, dest_lnglat) -> dict | None` — `GET /v3/direction/driving`（城际参考）
- `walking(...)` — `GET /v3/direction/walking`（近距离步行兜底）

返回统一精简结构：`{mode, summary, duration_min, distance_m, polyline}`。`polyline` 从 segments 的 walking/bus 段拼出（GCJ-02）。

### 5. `prompts.py`
- `EXTRACT_PROMPT`：字段加 `departure`（出发城市，可空字符串）。
- `PLAN_PROMPT`：改为输出 JSON `{"markdown": "...", "days": [{"day":1,"spots":["故宫","景山公园"]}]}`，`spots` 按当天游览顺序列出景点名（供交通查询）。

### 6. `nodes.py`
- `DEFAULT_PREFERENCES` 加 `departure: ""`。
- `extract_preferences`：解析后若 `departure` 为空，回填 `state.get("profile_departure", "")`。
- `generate_itinerary`：用现有 `_parse_json` 解析 JSON 输出，拆出 `markdown` 与 `days`（`days` 存进 state 的 `plan_days`）；解析失败则回退为「整段当 markdown、`plan_days=[]`」，流程不中断。
- 新增 `plan_transport(state)` 节点：
  1. 读 `prefs.departure` 与 `plan_days`；无 key / 无景点则直接透传空 transit。
  2. 对每站 `geocode("城市+景点名", 城市)` 去重取坐标（run 内缓存）。
  3. 相邻景点两两调 `transit`（距离近则 `walking`）；任一失败跳过该段。
  4. 若 `departure` 存在且 ≠ 目的地城市，调 `driving` 生成城际段。
  5. 组装 `transit`（含每段 from/to 名称+经纬度+polyline）；并按 `## Day N` 切分 markdown，把「🚇 交通」块注入每天末尾（markdown 注入失败则只存结构化 transit，正文不动）。

### 7. `state.py`
加 `profile_departure: str`、`plan_days: list`、`transit: dict` 字段。

### 8. `graph.py`
`extract → research → plan → plan_transport → END`（导入并 add 新节点）。

### 9. `routers/trips.py`
- 加 `_initial_state(user_input)`：读 profile 表得 `profile_departure`，供两处（invoke / astream）复用。
- `_to_response` 加 `transit` 字段。
- 落库时把 `transit` 写入 Trip；若最终 `preferences.departure` 非空则 upsert 到 profile（输入里说过出发地也顺手记住）。
- 新增 `GET /api/profile`、`POST /api/profile`（`{departure}`）两个端点。

### 10. `.env.example`
加 `AMAP_WEB_KEY=`（注释说明去 lbs.amap.com 申请）。

## 降级 / 失败处理

- `AMAP_WEB_KEY` 为空 → `plan_transport` 直接透传空 `transit`，行程照常纯文本。
- 单次 geocode / transit 失败 → 跳过该段，不影响其余段和整体流程。
- `plan` JSON 解析失败 → 回退整段 markdown、`plan_days=[]`，无交通、无地图。
- 前端 JS API 加载失败（key 未配 / 域名未绑定）→ 地图 tab 显示占位提示，不崩溃。

## 验证方式

1. 后端：填 `AMAP_WEB_KEY` 后 `uvicorn app.main:app --reload`，用 `/docs` 手动调 `POST /api/generate`，确认返回含 `transit` 结构化字段、markdown 里出现「🚇 交通」块。
2. 前端：填 `.env` 后 `npm run dev`，生成一次行程，确认：每日行程出现交通、新增「地图路线」tab 能显示 marker 和路线、头部出现「设置出发地」条，保存后 `GET /api/profile` 能读到。
3. 边界：不配 key / 配错 key / 跨城目的地，确认都能优雅降级不报错。
4. 回归：确认原有小红书进度、三步进度条（现四步）、复制/重新生成/历史列表不受影响。
