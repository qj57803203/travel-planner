# 多轮对话修改行程 — 实施方案

## Context

当前系统是单次生成模式：用户输入 → 跑 5 节点 DAG → 返回结果。用户生成行程后想修改（如"行程太紧了"、"不想去XX"），只能重新输入全部需求。本次改动让用户在生成结果后直接用自然语言提修改意见，Agent 在上一轮结果基础上增量修改，跳过不必要的 research 节点提速。

## 改动概览

```
后端：models → schemas → state → prompts → nodes → graph → routers → main（迁移）
前端：types → api → store → ItineraryView.vue（对话 UI + 推荐提问）
```

---

## 一、后端改动

### 1. `backend/app/models.py` — Trip 表新增字段

```python
# Trip 新增两列
parent_id: Mapped[int | None] = mapped_column(Integer, nullable=True)       # 关联原始行程
chat_history: Mapped[list | None] = mapped_column(JSON, nullable=True)       # 对话历史
```

### 2. `backend/app/main.py` — 轻量迁移

在已有的 `ALTER TABLE` 迁移块中补上 `parent_id` 和 `chat_history` 两列。

### 3. `backend/app/schemas.py` — 接口模型

```python
class GenerateRequest(BaseModel):
    user_input: str
    trip_id: int | None = None   # 修改模式：传入要修改的行程 ID

class ChatMessage(BaseModel):
    role: str                    # "user" | "assistant"
    content: str

class TripResponse(BaseModel):
    # 已有字段不变，新增：
    chat_history: list[ChatMessage] = []
    parent_id: int | None = None
```

### 4. `backend/app/agent/state.py` — AgentState 新增字段

```python
chat_history: list         # 对话历史 [{"role": "user"|"assistant", "content": str}, ...]
previous_itinerary: str    # 上一轮行程 markdown
is_modification: bool      # True = 修改模式
```

### 5. `backend/app/agent/prompts.py` — 新增修改模式提示词

新增 `MODIFY_PLAN_PROMPT`，与 `PLAN_PROMPT` 结构类似，但额外传入：
- `previous_itinerary`：上一轮行程原文
- `chat_history`：格式化后的对话历史
- 指令：在原有行程基础上按用户反馈修改，不要从头生成；保持不变的部分原样保留

同时新增 `MODIFY_EXTRACT_PROMPT`，用于修改模式下只提取用户的修改意图（不需要重新抽全部偏好）。

### 6. `backend/app/agent/nodes.py` — 节点逻辑改造

**`extract_preferences`：**
- 如果 `state["is_modification"]` 为 True：
  - 用 `MODIFY_EXTRACT_PROMPT` 从 chat_history 最后一条提取修改意图
  - 将修改意图 merge 到上一轮 preferences（如 pace 改"轻松"、去掉某 interest）
  - 返回 merged preferences + 标记 destination 是否变化
- 否则：走原有逻辑不变

**`research`：**
- 如果 `is_modification` 且 destination 未变：直接复用 `state["research"]`（上一轮数据），跳过爬取
- 否则：走原有逻辑

**`generate_itinerary`：**
- 如果 `is_modification`：用 `MODIFY_PLAN_PROMPT`，传入 previous_itinerary + chat_history
- 否则：走原有逻辑

### 7. `backend/app/agent/graph.py` — 加条件分支

```python
def after_extract(state):
    """修改模式且目的地未变时跳过 research。"""
    if state.get("is_modification") and not state.get("_destination_changed"):
        return "plan"      # 跳过 research
    return "research"

# 边改为：
g.add_conditional_edges("extract", after_extract, {"plan": "plan", "research": "research"})
```

### 8. `backend/app/routers/trips.py` — 接口改造

**`generate_trip` / `generate_trip_stream`：**
- 当 `req.trip_id` 不为空时：
  1. 从 DB 读取上一轮 Trip
  2. 校验轮数上限（沿 parent_id 链计数，≥5 拒绝）
  3. 构造带历史的初始状态：
     ```python
     {
         "user_input": req.user_input,
         "chat_history": old_trip.chat_history + [
             {"role": "assistant", "content": old_trip.itinerary},
             {"role": "user", "content": req.user_input},
         ],
         "previous_itinerary": old_trip.itinerary,
         "preferences": old_trip.preferences,
         "research": old_trip.research,
         "is_modification": True,
         "profile_departure": ...,
     }
     ```
  4. 新 Trip 的 `parent_id` 指向原始行程（始终指向链头），`chat_history` 累积
- 当 `trip_id` 为空时：走原有逻辑不变

## 二、前端改动

### 1. `frontend/src/types/index.ts`

```typescript
export interface ChatMessage {
  role: 'user' | 'assistant'
  content: string
}

// Trip 新增
export interface Trip {
  ...
  chat_history?: ChatMessage[]
  parent_id?: number
}
```

### 2. `frontend/src/api/trips.ts`

`generateTripStream` 增加可选 `tripId` 参数，body 中带上 `trip_id`。

### 3. `frontend/src/store/trip.ts`

- 新增 `async modify(input: string)` action：类似 `generate`，但调用时传入 `store.current.id` 作为 `trip_id`
- 新增 `chatRound` 计算属性：当前对话轮数（chat_history 长度 / 2）

### 4. `frontend/src/components/ItineraryView.vue` — 对话式 UI

**核心改动：生成结果后，整个 result 区域变成对话框样式**

```
┌─────────────────────────────────────┐
│ 📍 东京 5天 轻松  [重新生成] [复制]  │  ← result-head 不变
├─────────────────────────────────────┤
│                                     │
│  （现有内容：酒店推荐 + tabs 行程）   │  ← 原样保留
│                                     │
├─────────────────────────────────────┤
│ 💬 推荐提问：                        │  ← 推荐问题按钮
│ [行程太紧了] [不想去浅草寺] [换酒店]  │
├─────────────────────────────────────┤
│ [输入修改意见...          ] [发送]   │  ← 小输入框
└─────────────────────────────────────┘
```

**推荐提问**（根据行程动态生成 3-4 个）：
- "行程太紧了，节奏放轻松一点"
- "不想去{某景点}，换个地方"
- "多安排一些美食"
- "住宿换到{某区域}"

**对话历史展示**：用户消息以气泡形式追加在行程上方，agent 回复直接替换行程内容（原地更新，不堆气泡）。

**轮数限制**：达到 5 轮后输入框灰掉，提示"已达最大修改次数，请新建行程"。

## 四、验证方式

1. **首次生成**：正常生成行程，确认 chat_history 为空、功能不受影响
2. **修改行程**：生成后输入"行程太紧了"，确认跳过 research、plan 基于上一轮修改
3. **轮数限制**：连续修改 5 次后，第 6 次应被拒绝
4. **目的地变更**：修改时改目的地（如"换成大阪"），确认重新走 research
5. **推荐提问**：确认推荐按钮可点击、自动填入输入框
6. **历史记录**：修改后的历史列表中，确认 parent_id 链正确
